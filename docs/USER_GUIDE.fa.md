# راهنمای ساده priceactioner

راهنمای داخل برنامه: http://localhost:3000/docs

## اولین تست آموزشی

این مثال فقط برای شناخت فرم است، نه توصیه خرید:

1. برنامه را در http://localhost:3000 باز کن.
2. `BUY BTC` را انتخاب کن.
3. زمان اقدام را `NOW` و مدت نگهداری را `7 DAYS` بگذار.
4. ریسک را `BALANCED` و اولویت را `AVOID A BAD ENTRY` انتخاب کن.
5. اگر بیت‌کوین نداری، `I already own BTC` را تیک نزن. اگر داری، تیک بزن؛ قیمت ورود اختیاری است.
6. `ANALYZE BTC` را بزن.
7. خروجی ساختار، حمایت/مقاومت، حجم، مومنتوم و نوسان را بخوان. این کار سفارشی ثبت نمی‌کند.

«زمان اقدام» یعنی چه زمانی تصمیم می‌گیری. «مدت نگهداری» یعنی بعد از ورود چقدر می‌خواهی نگه داری. این دو با هم فرق دارند.

برای این مثال هفت‌روزه، تایم‌فریم اصلی 4h است و وزن‌ها چنین‌اند: 1h برابر ۱۵٪، 4h برابر ۴۵٪، و 1d برابر ۴۰٪. ریسک، اولویت و قیمت ورود در ورودی ثبت می‌شوند؛ فعلاً شاخص‌های واقعی بازار را تغییر نمی‌دهند و توصیه شخصی نمی‌سازند.

## دیدن پرامپت/ورودی دقیق

بعد از نتیجه، پنجره `REQUEST.PREVIEW` را باز کن:

- `READABLE`: خلاصه قابل‌خواندن.
- `STATE`: فرم تو + داده‌های محاسبه‌شده Python در DecisionContext.
- `QUESTIONS`: شش سؤال ثابت.
- `FULL REQUEST`: JSON کامل و دقیق همان تحلیل.
- `COPY FULL REQUEST`: کپی همان JSON، بدون هیچ کلید API.

درخواست یک پرامپت آزاد نیست؛ ساختار آن `model + state + questions` است. فرم داخل `state.user_intent` قرار می‌گیرد. Python افق، ساختار، مناطق، شاخص‌ها، شواهد و شرایط بی‌اعتبار شدن تحلیل را اضافه می‌کند. مقادیر بازار در هر تحلیل تغییر می‌کنند؛ سؤال‌ها ثابت‌اند.

نام سؤال‌ها: `direction`، `horizon_fit`، `trend_persistence`، `evidence_quality`، `risk` و `supports_user_plan`.

فعلاً این فقط یک پیش‌نویس محلی قابل بررسی است. هیچ درخواست خارجی فرستاده نمی‌شود و قرارداد نهایی API زنده TypeSafe هنوز تأیید نشده است.

## سهمیه روزانه

سه تحلیل موفق در روز برای هر مرورگر. نیمه‌شب UTC سهمیه تازه می‌شود. خطاهای عادی سهمیه را برمی‌گردانند. سهمیه محلی در JSON و روی سرور در MongoDB ذخیره می‌شود و با ری‌استارت عادی از بین نمی‌رود. نمودار، راهنما و پیش‌نمایش خروجی درخواست تحلیل جدید حساب نمی‌شوند.

بدون حساب کاربری نمی‌توان هر شخص را قطعی شناسایی کرد. مرورگر یا دستگاه دیگر سهمیه جدا دارد و پاک‌کردن کوکی این محدودیت را دور می‌زند. برای اجرای سخت‌گیرانه «هر شخص» باید احراز هویت کاربران اضافه شود.

## یوزرنیم و پسورد ادمین

روی کامپیوتر فعلی، حساب `admin` با رمز انتخابی خودت وجود دارد و هنگام تغییر ذخیره‌سازی حفظ شده است. نسخه ZIP حساب و رمز شخصی تو را ندارد. برای ساخت حساب روی کامپیوتر جدید یا تغییر رمز محلی، در ترمینال ریشه پروژه اجرا کن:

```powershell
cd backend
..\.venv\Scripts\python.exe setup_admin.py
```

نام را وارد کن یا برای `admin` Enter بزن. سپس پسورد دلخواه حداقل ۱۲ کاراکتری را دو بار وارد کن. موقع تایپ پسورد چیزی روی صفحه دیده نمی‌شود؛ طبیعی است. فقط هش پسورد در محل ذخیره رکوردها ثبت می‌شود. برای حساب سرور، مراحل [راهنمای انتشار](DEPLOYMENT.fa.md) را انجام بده.

بعد بک‌اند را ری‌استارت کن:

```powershell
..\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

اگر بک‌اند از قبل اجراست، اول همان فرایند را متوقف کن تا پورت آزاد شود. ورود ادمین: http://localhost:3000/admin/login

در ادمین، `HISTORY` تحلیل موردنظر را انتخاب می‌کند؛ `DECISION.CONTEXT` داده‌ها را نشان می‌دهد؛ `JEV.PREVIEW` پیش‌نویس دقیق را نشان می‌دهد.

## کلید Jev را دقیقاً کجا بگذارم؟

فایل محلی واقعی تنظیمات:

`C:\Users\EliteBook\Desktop\PriceActioner\backend\.env`

کلید فقط در این سطر قرار می‌گیرد:

```dotenv
JEV_API_KEY=YOUR_REAL_KEY_HERE
JEV_MODE=disabled
```

فایل `.env.example` فقط نمونه است. کلید را در آن، در frontend، در متغیر `NEXT_PUBLIC_...` یا داخل چت نگذار. بعد از تغییر `.env` بک‌اند باید ری‌استارت شود.

روی Vercel، محل این کلید Settings → Environment Variables در پروژه **backend** است؛ پس از تغییر باید Redeploy کنی.

گذاشتن کلید به‌تنهایی Jev را فعال نمی‌کند. تا وقتی تحلیل و ورودی تولیدشده را بررسی نکرده‌ای، `JEV_MODE=disabled` بماند. کد ارسال زنده هنوز پیاده نشده؛ تغییر حالت به `live` فعلاً مانع شروع بک‌اند می‌شود.
